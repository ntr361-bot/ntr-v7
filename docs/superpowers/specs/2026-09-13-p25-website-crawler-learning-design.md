# P25 网站资料爬取与自学习设计

## 目标

把网站资料从一次性生肖计数升级为可审计的学习闭环：每天抓取并归档各栏目资料，使用网站随后公开的开奖结果建立初始结算样本，持续计算每个栏目的可靠度，并用动态权重融合当期预测。

## 原则

- 网站是起步阶段的资料与开奖结果来源；系统不预设任何栏目可信。
- 每个期号、每个栏目独立归档和结算。往期资料用于计算准确率，绝不作为新一期的原始预测内容。
- 本地开奖库可记录同期期号的交叉校验状态，但不覆盖网站抓到的原始结果、网页快照或来源哈希。
- 已生成的预测及其输入快照冻结；后续学习只能更新未来期的权重，不能反写历史预测。

## 数据模型

新增持久化的资料档案，最小单位是“期号 + 来源栏目 + 抓取版本”。每条档案保存：完整期号、网站短期号、来源脚本地址、内容哈希、抓取时间、目标期原始区块、解析出的生肖、抓取状态与错误原因。

结算记录与资料档案关联，保存网站公布的实际生肖、结果抓取时间、是否为占位结果、与本地开奖库是否一致，以及该栏目对该期的 Top3/Top6 命中结果。相同内容哈希不重复写入；网站内容更新时保留新版本而不覆盖旧快照。

栏目权重由已结算样本计算，包含长期 Top3/Top6 命中率、近期加权表现、样本量置信度和连续稳定性。样本少时向均等权重收缩；随着每天结算逐步由自身数据主导。权重计算的输入样本和结果版本都需要可追溯。

## 每日流程

1. 在现有每日 17:10 自动任务中，计算完整目标期号和网站短期号。
2. 下载页面及四类候选脚本，保存原始内容和哈希；只从目标期区块生成当期预测信号。
3. 同时遍历脚本里出现的往期期号，将每一期切成独立区块归档。未出现生肖、内容无效或已经过期但尚无结果时不伪造信号。
4. 对资料中出现真实“开：生肖号码”的已开奖期，建立网站结果结算；对本地库已有的同期开奖仅标记一致性。
5. 用所有已结算档案重算栏目权重，再以当期栏目资料和这些权重融合，保存冻结的 P25-Web 预测、来源快照、权重快照和排序。
6. 后续运行重复抓取、补全未结算期并更新未来预测所用权重；不会覆盖已有 P25-Web 预测或旧档案版本。

## 失败处理

网页、单个脚本或单一期块解析失败时，记录失败档案并继续处理其他来源。若目标期没有任何有效栏目，停止发布本期预测。若网站公布结果与本地开奖库冲突，保留双方证据、标记冲突，并排除该期对权重的自动更新，等待人工核对。

## 测试与验收

- 多期脚本被逐期拆分：256 期资料不包含 255 或 257 的生肖与开奖信息。
- 往期已开奖资料能进入结算；问号占位符不能被当成结果。
- 相同网页内容重复抓取不重复建档；内容更新产生可追溯的新版本。
- 栏目历史样本更好时，其权重与对当期排名的影响更高；样本不足时不会出现极端权重。
- 已冻结的 2026256 P25-Web 记录不被改写；新逻辑从后续可用期开始生效。
