# P25 目标期资料解析修复设计

## 目标

修复网站资料解析器把同一脚本内往期资料的生肖混入目标期预测的问题。第 2026256 期只允许使用网站第 256 期对应区块中的内容。

## 范围

修改 `WebsiteLearningService.cs` 的解析和抓取接口，并在现有测试项目中增加回归测试。不引入新的 HTML 解析依赖，不改动预测模型、来源权重算法或数据库结构。

## 设计

调用方把目标短期号传给 `WebsiteLearningService.FetchAsync`。解析器在规范化脚本文本中定位目标期号，并截取该期号起点到下一个不同期号起点之间的单一区块。期号、生肖、开奖状态都只从该区块解析。

每个来源最多产出一个目标期信号。目标期区块不存在、已经包含实际开奖结果或没有可识别生肖时，该来源不可用，由抓取服务跳过。`WebsiteLearningIntegration.Publish` 先计算 `targetIssue % 1000`，再抓取该目标期资料，确保数据库目标期和网站期号在解析入口就绑定。

## 数据流

1. `Publish(2026256)` 计算网站目标期 `256`。
2. `FetchAsync(page, 256)` 获取页面和候选脚本。
3. `Parse(text, sourceId, sourceHash, 256)` 仅截取 256 期区块。
4. 有效来源参与生肖计数和排序。
5. 没有任何有效来源时停止写入；存在有效来源时保持现有首次快照和幂等写入语义。

## 开奖识别

在检查开奖状态前先移除 HTML 标签并解码文本。`开:？00`、`开：?` 等占位符属于开奖前内容；`开:猪44`、`开：蛇02` 等实际值属于开奖后内容。往期区块中的开奖结果不会影响目标期区块。

## 测试

回归测试使用手写的多期脚本片段验证：

- 256 期“猴龙蛇羊虎牛”只返回这六个生肖，不能吸收 255 期的猪、鼠等生肖。
- 256 期只有“大双大单小单”时因没有生肖而被跳过，不能从 255 期开奖“猪44”提取猪。
- 目标期不存在时拒绝该来源。
- 目标期出现真实开奖结果时拒绝该来源，问号占位符仍可解析。
- `Publish`/排名相关的现有测试继续通过。
