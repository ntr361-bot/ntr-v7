# V7 独立学习模型设计

## 已确认边界

保留两个现有自动学习模型，不改变其评分、权重、学习行为或历史记录。新增第三个旁路学习模型，先验收入口，未通过不接入正式预测。依赖优先使用本地缓存。

## 现状与风险

当前未提交的 OnlineLearningPipeline 仍使用 ExperimentModels.AutoLearning（v65-auto）作为身份，且含更新正式 PredictionHistory 学习状态的代码。它仅在临时验收作用域启用，但不能原样作为独立模型投入运行。

需要逐项审查此前共享 AutoLearningEngine、AutoLearningTrainer 的变更，不能仅关闭新入口就声称旧模型完全未动。只撤除本阶段引入且影响旧行为的改动，保留其他既有改动，不整体回退文件。

## 方案比较与选择

1. 推荐：独立数据库、独立入口与学习实现。隔离最明确，便于检查旧数据零变化。
2. 同库独立表与模型键：改动较少，但共享连接和事务容易误写旧表。
3. 只换模型名称：无法隔离状态，不采用。

## 独立模型

- 展示名称：V7 独立学习（实验）。模型键：v7-independent-learning-v1。
- 专用文件：数据目录下 experiments/v7-independent-learning-v1/learning.db。
- 独立保存输入快照、完整12生肖预测、记忆版本、权重和学习审计。
- 不调用旧模型的保存与学习入口，不写正式 PredictionHistory、ModelMemory 或 daily-records。
- 不复制旧模型训练记忆。首次使用明确的初始参数，历史训练结果标注为重放，不能冒充开奖前预测。
- 输入通过只读适配器提供：目标期之前的历史与可验证的基础模型结果。输入缺失或截止期违规则拒绝生成，不使用未来记忆补齐。
- 新学习实现可以基于现有机制独立封装，但不能通过修改共享学习函数改变两个旧模型。

## 闭环与失败处理

保存第N期预测及输入版本 → 确认第N期开奖 → 使用冻结输入学习 → 同一事务写入记忆和审计 → 第N+1期使用更新后的版本。

同一期成功学习只能执行一次；失败事务不递增版本；补学必须按顺序；缺少快照时明确停止或以独立历史重放运行，不覆盖原预测。默认不接入生产定时任务、界面或云端发布。

## 本阶段验收

1. 使用临时数据库与固定测试输入，不训练真实生产数据。
2. N预测、N学习、N+1版本引用完整通过。
3. 重复调用不改变记忆；注入写入失败能够原子回滚。
4. 目标期及未来期输入被拒绝；乱序补学被拒绝。
5. 新模型运行前后，两个旧模型的记忆和历史记录逐字节一致。
6. 旧学习行为回归测试通过，软件离线构建通过。
7. 报告区分已验收、本地旁路、尚未接入每日运行，不能以编译成功代替闭环验收。

## 阶段停止点

本轮设计确认后实施独立入口与验收。通过后报告，再决定每日旁路运行与显示方式；不自动上线，不推送或发布。
