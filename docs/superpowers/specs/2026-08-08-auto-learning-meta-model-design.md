# 当前版本自动学习元模型设计

## 1. 目标与边界

在当前六合分析软件内增量加入自动学习能力，不修改主预测界面，不增加版本号，不删除或替换 V6.3、V7、V8.2、V8.3 模块。现有预测逻辑继续作为基础模型，新增元模型负责汇总基础模型结果并生成最终十二生肖排序。

系统必须满足以下边界：

- 预测第 N 期时只能读取期号小于 N 的开奖、预测和学习状态。
- 第 N 期开奖写入后，才允许使用第 N 期结果更新模型记忆。
- 同一预测记录只能学习一次，重复启动或重复导入开奖不能重复调整。
- 学习异常、样本不足或参数损坏时，自动退回现有固定预测结果。
- 不恢复已经取消的五行特征，不启用已经删除的 200 期模型。
- 不从云端导入缺少完整分项评分的预测记录。

## 2. 总体架构

正式预测分成基础层、元模型层、反馈层和持久化层。

1. 基础层保留当前 AI、ML、状态、规则模型。每个基础模型独立输出十二生肖分数和排名。
2. 元模型层由 `MetaPredictionEngine` 读取四个基础模型的分数、排名、市场状态和 `FeatureEngine` 特征，输出最终十二生肖概率排序。
3. 反馈层由 `AutoLearningEngine` 在开奖验证完成后计算命中、真实生肖排名、基础模型贡献、特征贡献和失败类型。
4. `WeightOptimizer` 根据反馈更新模型系数，单次调整最多 5 个百分点，单项限制在 0%–70%，总和归一化为 100%。
5. `ModelMemory` 将参数、表现、连续失败、特征贡献和调整历史保存到数据库，程序启动时直接加载。

元模型不是新的独立“猜测器”。它必须以当前基础模型结果为输入，因此现有逻辑仍然是预测依据。最终 TOP3、TOP6 由元模型排序截取。

## 3. 元模型计算

### 3.1 输入

对每个生肖构造一行元特征：

- AI 模型归一化分数与排名。
- ML 模型归一化分数与排名。
- 状态模型归一化分数与排名。
- 规则模型归一化分数与排名。
- 当前市场状态概率。
- 频率、遗漏、周期、动量、重复、趋势等现有特征组。
- 基础模型一致度、最高与最低分差、排名方差。

所有输入必须由截止到目标期前一期的数据生成。预测时保存输入快照，开奖后学习只能使用该快照，不能用重新计算后的未来数据替代。

### 3.2 初始训练

初始训练使用 2023–2025 年数据，按期号升序执行一次严格滚动训练。每个训练样本的特征只使用其前序数据。初始基础模型贡献为 AI 40%、ML 40%、状态 20%、规则 0%。

元模型采用十二生肖排序损失：真实生肖作为正样本，其余生肖作为负样本，优化真实生肖相对排名。输出经 softmax 归一化为十二生肖概率。

### 3.3 开奖后增量学习

每期开奖验证后进行一次增量更新：

- 计算实际生肖的最终排名、TOP3/TOP6 命中和倒数排名 MRR。
- 计算四个基础模型对真实生肖排名的正负贡献。
- 计算特征组对真实生肖相对分差的贡献。
- 更新最近 100 期表现和最多 500 期的衰减统计。
- 调用 `WeightOptimizer` 做一次受约束调整。
- 保存调整前后参数、原因和时间。

连续失败设为两个独立触发器：TOP3 连续 5 期未命中，或 TOP6 连续 3 期未命中。任一条件满足后，分析对应连续窗口中持续拉低真实生肖排名的基础模型和特征组，降低相应系数；不对单期失败做大幅修正。TOP3 命中时只重置 TOP3 连续失败计数，TOP6 命中时只重置 TOP6 连续失败计数；同一失败序列的同一阈值只触发一次。

### 3.4 安全回退

满足任一条件时不采用元模型输出：

- 可用已开奖训练样本少于 100 条。
- 输入快照缺少十二生肖完整基础分数。
- 参数存在 NaN、无穷值或权重和无法归一化。
- 元模型最近 30 期 TOP6 命中率比固定模型低 10 个百分点以上。

回退时使用现有固定模型排序，仍保存预测快照，但不伪造元模型结果。

## 4. 数据库设计

现有 `PredictionHistory` 已包含期号、预测时间、TOP3、TOP6、号码、模型、实际开奖、命中、分项评分和学习信息。使用兼容迁移增加以下字段：

- `FinalRankingJson TEXT DEFAULT ''`：十二生肖最终排名和概率。
- `BaseModelScoresJson TEXT DEFAULT ''`：四个基础模型的十二生肖分数。
- `FeatureSnapshotJson TEXT DEFAULT ''`：预测当时的特征快照。
- `WeightSnapshotJson TEXT DEFAULT ''`：预测当时使用的参数。
- `ActualRank INTEGER DEFAULT 0`：开奖后真实生肖排名。
- `LearningStatus TEXT DEFAULT 'Pending'`：`Pending`、`Learned` 或 `Skipped`。
- `LearnedAt TEXT DEFAULT ''`：完成反馈时间。

新增 `ModelMemory` 表：

- `MemoryKey TEXT PRIMARY KEY`。
- `MemoryJson TEXT NOT NULL`。
- `UpdatedAt TEXT NOT NULL`。

新增 `LearningAdjustmentHistory` 表：

- `Id INTEGER PRIMARY KEY AUTOINCREMENT`。
- `Issue TEXT NOT NULL`。
- `AdjustedAt TEXT NOT NULL`。
- `OldWeightsJson TEXT NOT NULL`。
- `NewWeightsJson TEXT NOT NULL`。
- `FeatureContributionJson TEXT DEFAULT ''`。
- `Reason TEXT DEFAULT ''`。

迁移只增加字段和表，不修改或删除现有开奖记录与有效预测记录。

## 5. 代码组件

### 5.1 `MetaPredictionEngine.cs`

负责构造元模型输入、计算十二生肖最终概率、训练一次初始模型、开奖后单样本更新、检测异常并回退。对外返回完整排序、TOP3、TOP6、是否回退和回退原因。

### 5.2 `AutoLearningEngine.cs`

负责查找 `Pending` 且已开奖的预测，逐条计算反馈并更新记忆。处理完成后原子地标记 `Learned`；资料不完整则标记 `Skipped` 并记录原因。

### 5.3 `ModelMemory.cs`

定义可序列化的模型状态：当前基础模型权重、元模型系数、最近 100 期指标、TOP3 与 TOP6 各自的连续失败次数、最多 500 期的特征贡献、最近调整和训练截止期。加载失败时返回安全默认值，不覆盖损坏原值。

### 5.4 `WeightOptimizer.cs`

接收旧权重和表现反馈，输出满足约束的新权重。每个分量相对旧值最多变化 0.05，范围 0–0.70，最终总和为 1.0。连续失败触发的调整也必须遵守同一边界。

### 5.5 现有文件集成

- `AIEngine.cs`：保留现有预测，补充基础模型快照并调用元模型排序；保存预测后不立即学习。
- `FeatureEngine.cs`：提供按特征组输出和贡献计算所需的稳定名称，不改变现有特征含义。
- `EnsemblePredictionService.cs`：暴露规则与组合模型的十二生肖完整分数，不删除原有接口。
- `MachineLearningPredictionService.cs`：暴露 ML 十二生肖完整分数和模型状态，不在预测期使用目标结果。
- `DatabaseHelper.cs`：执行兼容迁移、保存快照、幂等读取待学习记录和原子更新。
- `DatabaseHelper.VerifyPrediction` 与重算流程：开奖写入和命中验证完成后调用自动学习。
- `AIPredictHistoryForm.cs`：只在现有智能预测历史窗口增加“学习报告”按钮；主预测界面保持不变。

## 6. 特征贡献

特征按稳定分组统计：频率、遗漏、周期、动量、短周期重复、趋势、市场状态和模型一致度。单期贡献使用该组对真实生肖相对十一生肖平均分差的影响计算，命中期记录正贡献，未命中期记录负贡献。

报告使用最近最多 500 期的时间衰减绝对贡献归一化为百分比。贡献分析只解释和调整元模型，不回写或篡改历史预测结果。

## 7. 自动学习报告窗口

从现有“智能预测历史”窗口的“学习报告”按钮打开独立窗口，显示：

- 当前状态：正常、样本不足、回退或连续失败检查。
- 最近 100 期 TOP3、TOP6、MRR 和最大连续未命中。
- AI、ML、状态、规则当前贡献百分比。
- 贡献最高的三个特征组。
- 最近调整的日期、期号、旧权重、新权重和原因。

报告窗口只读取数据库和 `ModelMemory`，不在打开窗口时触发训练。

## 8. 验证设计

### 8.1 单元与集成测试

- 数据库迁移保留原记录并增加新字段、表和索引。
- 预测保存包含排名、基础分数、特征和权重快照。
- 同一期反馈重复执行不会重复学习。
- 权重单次变化不超过 5%，单项不超过 70%，总和为 100%。
- 参数损坏、样本不足和表现退化正确回退。
- 第 N 期特征构造不能读取第 N 期及之后开奖记录。
- TOP3 连续 5 期未命中触发失败分析。
- TOP6 连续 3 期未命中触发失败分析。
- 模型记忆保存后重新启动可恢复相同参数。

### 8.2 2023–2026 对比

1. 2023–2025 按期号顺序训练初始元模型，每一期只使用之前数据。
2. 以 2025 年末状态开始 2026 测试。
3. 对每个 2026 测试期，固定模型和自动学习模型使用完全相同的历史截止点分别预测。
4. 记录预测后才揭示真实结果；自动学习模型更新后再进入下一期。
5. 输出 TOP3、TOP6、MRR、最大连续未命中和逐年/逐月稳定性。

只有自动学习模型在未使用未来数据的前提下指标真实提高，才能得出“提升”结论；否则报告为“未发现稳定提升”，保留回退保护，不夸大效果。
