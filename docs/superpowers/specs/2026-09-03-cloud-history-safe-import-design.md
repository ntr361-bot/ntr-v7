# V7 云端预测历史安全导入设计

## 目标

桌面端启动和每 15 分钟同步时，将云端已生成、但本机尚未拥有的完整预测记录写入本地 `PredictionHistory`。同步不得覆盖本机已有预测，也不得替换本机的自动学习记忆。

## 已确认的问题

云端日预测卡片只包含 100 期和自动学习的摘要，因此不能满足正式历史的完整快照校验。随后同步器尝试读取云端 `runtime-state` 的完整记录；当其中的 `auto-learning-meta-v2|v65-auto` 与本机记忆不同，现有逻辑抛出异常并中断整次同步，导致所有云端预测都无法进入本地历史。

## 方案

1. 日预测卡片仍只作为缓存；不降低正式历史快照的完整性要求。
2. 导入云端运行状态时，预测记录仍逐条按现有唯一键合并；本地已有记录或内容冲突时保留本机首个快照。
3. 自动学习记忆改为独立处理：本地为空时导入云端记忆；本地已存在且不同则保留本机、写入告警，不再抛出异常或阻断预测记录导入。
4. 同步结果需区分“导入的预测记录数”和“保留本机的冲突记忆数”，以便界面和日志准确说明状态。

## 数据安全边界

- 不删除、不重算、不覆盖 `PredictionHistory`。
- 不覆盖本机 `ModelMemory`。
- 不将摘要预测伪装成完整正式历史。
- 云端仅补齐本地缺少的完整预测快照。

## 验证

新增回归测试覆盖：

- 本机记忆与云端不同，但云端缺失预测记录仍能导入。
- 冲突记忆保留本机值。
- 本机记忆为空时仍会导入云端记忆。
- 摘要型云端卡片继续不会写入正式预测历史。
