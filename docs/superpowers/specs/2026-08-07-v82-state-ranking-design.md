# V8.2 状态识别与生肖排序设计

## 目标

在不覆盖 V6.3/V7 正式结果的前提下建立独立 V8.2 实验：先识别当前历史状态，再用与状态匹配的策略对 12 个生肖进行完整排序，并对生肖和波色分别执行严格滚动验证。

## 数据边界

- 预测第 N 期时只能读取第 N 期之前的数据。
- 状态阈值、交叉特征、排序模型参数和路由权重均不得利用第 N 期及以后开奖结果。
- 使用现有 1313 条有效记录；前 100 条作为最小训练期，后 1213 条作为严格滚动预测样本。
- V8.2 保持实验隔离，不修改 V6.3、V7 的数据库记录和正式预测入口。

## 架构

1. `MarketStateEngine` 从既有非五行特征计算四类状态分数：正常随机、短周期重复增强、冷热转换、遗漏释放。输出主状态、四类归一化概率、置信度和证据。
2. `FeatureEngine` 在现有 42 个非五行特征上增加交叉特征：遗漏×动量、近7期次数×短期过滤、重复频率×遗漏、长期趋势×近期趋势等。所有交叉项在单个历史前缀内计算。
3. `ZodiacRankingEngine` 使用成对排序目标：每个训练期把实际生肖作为正样本，与其余生肖构造特征差；模型学习“实际生肖应排在其他生肖之前”，最终输出 12 项分数、Softmax 概率和稳定排序。TOP3/TOP6仅由完整排序截取。
4. `V82StateRouter` 根据状态选择短期、中期、长期策略的组合权重，再与排序分数合成。路由表固定且可审计，不在完整数据上反向调参。
5. `ColorBacktestEngine` 独立滚动调用 `ColorEngine`，统计主波命中、防波覆盖、排除成功、最大连续错误；不得读取生肖预测。
6. `V82Evaluation` 输出总结果、分状态表现、状态分布、排序指标、波色指标和与 V7 ML 基线差值。

## 状态定义

- 正常随机：其他三类信号均不突出。
- 短周期重复增强：隔1/隔2重复、短周期重复及其趋势共同升高。
- 冷热转换：短中期频率差、动量反转和分布离散度升高。
- 遗漏释放：候选生肖的遗漏比率、遗漏偏离和平均遗漏共同升高。

状态不是对未来结果的标签；它只描述预测时已经可观察到的历史结构，因此不会把未来信息泄漏进特征。

## 验证指标

- 生肖：MRR、实际生肖平均名次、TOP1、TOP3、TOP6、最大连续TOP6错误。
- 状态：四类样本数、各状态TOP3/TOP6、状态置信度分布。
- 波色：主波命中率、主+防覆盖率、排除成功率、最大连续主+防错误。
- 对照：同一 1213 个目标期上的 V7 ML TOP3/TOP6。

## 验收标准

- 所有新增行为先有失败测试，再实现。
- 12生肖输出无重复、概率和为1、排序与概率一致。
- 状态和交叉特征满足前缀不变性测试。
- 1213期滚动验证完整生成机器可读 JSON 和中文 Markdown。
- 若 V8.2 未稳定超过基线，报告必须明确标记“未发现优势”，不得替换正式模型。
