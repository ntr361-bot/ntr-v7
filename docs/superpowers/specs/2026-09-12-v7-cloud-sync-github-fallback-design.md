# V7 云端预测同步：GitHub 主通道与云端备用通道

## 目标

让 V7 桌面端在启动和每 15 分钟同步时，稳定地把已发布的开奖、预测档案与运行状态更新到本地。桌面端不得因 `chatgpt.site` 的 Cloudflare 浏览器验证而停止同步。

## 设计

### 数据来源顺序

1. 优先读取 V7 正式仓库 `ntr361-bot/ntr-v7` 默认分支中的 `site/data` 文件。
2. 若 GitHub 数据源暂时不可用，再读取现有的 V7 云端接口。
3. 两个来源均失败时，不修改本地数据，界面显示失败原因，并保留下一次 15 分钟自动重试。

GitHub 数据源只读取工作流已提交的文件：`history.json`、`daily-records/manifest.json`、每期预测 JSON 与 `runtime-state.json`。不读取构建产物、数据库或用户电脑中的其他目录。

### 同步与数据完整性

保留现有同步顺序和校验：先导入开奖历史，再读取预测清单；每个预测文件先缓存后只在完整模型快照通过校验时写入 `PredictionHistory`；最后合并同构运行状态。重复同步继续由现有合并逻辑去重，不覆盖本机特有的有效记录。

备用接口仍使用原来的 URL；GitHub 主通道成功时不再请求该接口，避免无意义的 Cloudflare 403 日志。

### 状态与错误

同步结果应携带实际使用的数据来源。主通道成功时界面明确显示“GitHub V7 正式数据”；主通道失败但备用成功时显示“备用云端”；两者失败时记录两条可辨识的错误摘要，便于判断是 GitHub 不可达还是云端被拦截。

### 测试

测试覆盖：GitHub URL 的资源映射；主通道成功时不走备用；主通道失败时进入备用；两个通道都失败时不导入部分数据；以及现有完整预测档案可写入本地历史的行为不回归。构建 V7 和运行现有冒烟测试；若仓库既有的独立失败出现，会单独报告，不将其归因于本修复。

## 不在本次范围

- 不改预测算法、V6.5 自动学习显示逻辑或 V7 模型结果。
- 不调整 Cloudflare 网站配置。
- 不新建运行目录、隔离目录或桌面快捷方式。
